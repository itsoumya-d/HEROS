## YYYY-MM-DD - Missing jq Type Checks in MCP Bridge
**Vulnerability:** The forge/mcp-bridge.sh script does not type-check the JSON parameters (`params`, `params.arguments`, `params.name`) before accessing them with `jq` in the `tools/call` handler, while `ledger/mcp-bridge.sh` correctly type-checks them. This can cause jq to fail with a non-zero exit code if the parameters are not objects or strings (e.g., if they are arrays), which triggers `set -e` and crashes the handler or causes an internal error response instead of properly reporting an invalid parameters error.
**Learning:** `jq` handles null values and types strictly in some scenarios. In bash scripts with `set -e`, a non-zero exit code from `jq` causes the script/function to fail abruptly, potentially crashing the server or producing unexpected errors. Ledger's bridge was updated with this fix (RT-345, RT-349, V339), but Forge's bridge was not, representing a defense-in-depth failure.
**Prevention:** Always port security enhancements and structural robustness fixes across all components that share the same architectural pattern (like the MCP bridge scripts). Explicitly type-check JSON parameters using `jq -e` before extraction to prevent unexpected command failures.
