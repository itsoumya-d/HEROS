## 2024-06-13 - jq Subprocess Overhead in Bash Loops
**Learning:** Repeatedly calling `jq` to parse the same JSON string in a bash script (e.g., inside a read loop) incurs significant subprocess creation overhead. Executing `jq` multiple times for individual field extractions makes the script CPU-bound and slow.
**Action:** Combine multiple JSON field extractions into a single `jq` invocation. When multiple distinct typed values are needed in bash, use the `jq` `@sh` filter to safely format strings, booleans, and nulls for `eval`. This prevents RCE while drastically reducing subprocess overhead (e.g., going from 7 jq calls to 1). Ensure explicit type checking within the `jq` script before passing to `@sh` (e.g., handling booleans with `tostring` and explicitly selecting string properties) to avoid fatal `jq` runtime errors and `bash` eval issues.
