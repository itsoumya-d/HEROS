## 2024-05-24 - Batching jq subprocesses in Bash using @sh
**Learning:** Parsing multiple JSON fields from the same payload using separate `jq` invocations causes significant subprocess spawning overhead. In the hot path (like an MCP message handler processing every request), this delay accumulates. However, `jq`'s `@sh` filter allows extracting multiple values in one invocation, formatting them safely as shell strings, which can then be safely loaded into a bash array using `eval "local arr=($parsed)"`. We must explicitly type-check properties in jq using `type == "string"` so non-string properties are coalesced to empty strings and boolean/object fields don't cause fatal jq runtime errors.
**Action:** Combine repeated `jq` field extractions into a single call returning an `@sh`-formatted array for safe evaluation whenever optimizing Bash scripts parsing JSON payloads.
